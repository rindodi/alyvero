# Alyvero Design System

## Product
Alyvero is a focused browser utility product for everyday PDF and image problems. The primary audience is someone who wants one file task solved quickly, often on mobile.

## Creative direction
**Instrumented utility desk** — a calm, precise workspace rather than a generic SaaS dashboard or a giant tools directory.

The interface should feel like a well-made digital instrument: clear controls, visible file state, quiet surfaces, strong typography, and one memorable visual signature.

## Visual tokens
- Ink: #17202B
- Paper: #F6F4EF
- Surface: #FFFFFF
- Rule: #D9D7D0
- Cobalt: #3155E7
- Coral: #E86A4A
- Mint: #2E8B78
- Muted: #68727D
- Soft blue: #EAF0FF
- Soft coral: #FBECE6
- Soft mint: #E8F3EF

## Typography
- Display: Georgia, "Times New Roman", serif — used sparingly for the main thesis and major editorial headings.
- UI/body: Inter, ui-sans-serif, system-ui, sans-serif — used for navigation, controls and readable copy.
- Utility labels: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace — used for file types, small metadata and status labels.

## Layout
- Maximum content width: 1180px.
- Desktop content uses generous horizontal margins and occasional asymmetric two-column compositions.
- Tool interaction surfaces remain visually dominant and centered.
- Mobile collapses to a single column with 16px page gutters.

## Signature
The **file specimen rail**: tool cards and upload surfaces use small document/image specimen drawings, tiny format labels and a vertical cobalt rule. It visually connects the product to the actual artifacts people are manipulating.

## Interaction
- Primary actions are cobalt, rectangular with a modest 10px radius.
- Secondary actions are white with a 1px rule.
- Cards use 14px radius, subtle rules and almost no shadow.
- Hover uses translation of 2–3px and border/ink contrast rather than large shadows.
- Focus rings are 3px with a visible cobalt offset.
- Respect prefers-reduced-motion.
- Never rely on color alone for status.

## Content voice
Specific, plain, practical. Name the user's action and expected result. Avoid exaggerated claims such as "perfect", "instant" or "100% secure" unless technically demonstrated.

## Accessibility
Target WCAG 2.2 AA. Use semantic links/buttons, visible focus, keyboard-accessible menus, stable loading geometry, readable contrast and reduced-motion support.
